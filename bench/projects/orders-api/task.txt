Направи JSON API за поръчки на малък онлайн магазин с Flask и SQLite — Python пакет shop/ с отделни модули: __init__.py (create_app), db.py (SQLite), validation.py (проверките и страниците), pricing.py (сметките), products.py, customers.py, orders.py и summary.py — последните четири са отделни Blueprint-а. from shop import create_app; create_app(db_path) връща Flask приложението, данните остават във файла db_path и след рестарт. Всички суми са цели числа в центове, цените на продуктите са без ДДС. Всеки отговор е JSON. Грешка във входа → 400 и {"errors": {"<поле>": "<съобщение>"}} с ВСИЧКИ сгрешени полета наведнъж; тяло, което не е JSON обект → 400; несъществуващ id → 404 и {"error": "..."}; конфликт → 409 и {"error": "..."}. Списъците (GET /products, GET /customers, GET /orders) се страницират с ?page=1&per_page=20 (това са подразбиранията), page ≥ 1, per_page от 1 до 100, иначе 400; отговорът е {"items": [...], "page", "per_page", "total"}, подредени по id; страница след последната → 200 с празен items. Продукти: POST /products {"name": непразен текст, "price_cents": цяло число > 0 (true, 12.5 и "100" не са валидни)} → 201 и {"id", "name", "price_cents"}; GET /products/<id>; PATCH /products/<id> с name и/или price_cents (същите проверки) → 200 и продукта. Клиенти: POST /customers {"name", "email"} → 201 и {"id", "name", "email"}; имейлът се пази без интервали в краищата и с малки букви и трябва да е от вида име@домейн.зона; същият имейл втори път (без значение от главните букви) → 409; GET /customers/<id>. Поръчки: POST /orders {"customer_id": id, "lines": [{"product_id": id, "qty": цяло число ≥ 1}, ...]} — lines е непразен списък; непознат клиент → 400 с поле customer_id, непознат продукт или лош ред → 400 с поле lines; един и същ продукт два пъти се слива в един ред със сбор от бройките (по реда на първата поява); отговор 201 и {"id", "customer_id", "status": "new", "lines": [{"product_id", "name", "qty", "unit_price_cents", "net_cents"}], "net_cents", "vat_cents", "total_cents"} — цената се запомня в момента на поръчката и по-късна промяна на продукта не я пипа; ДДС е 20% и се смята веднъж върху общата сума без ДДС (не по редове), закръглено до цент, половин цент нагоре; total_cents = net_cents + vat_cents. GET /orders/<id>; GET /orders може да филтрира с ?status= и ?customer_id= (непознат статус → 400). POST /orders/<id>/status {"status": "..."} — позволени са само new→paid, new→cancelled, paid→shipped и paid→cancelled → 200 и поръчката; всеки друг преход (и към същия статус) → 409; статус извън new, paid, shipped, cancelled → 400. GET /summary → {"orders": брой поръчки без отказаните, "by_status": {"new": n, "paid": n, "shipped": n, "cancelled": n} винаги с четирите ключа, "revenue_cents": сбор от total_cents на платените и изпратените, "top_products": до 3 [{"product_id", "name", "qty"}] по продадени бройки в платени и изпратени поръчки, най-много първо, при равенство по product_id}. Flask и pytest са инсталирани. Напиши тестове с test client-а на Flask в tests/ и ги пусни, докато минат.
