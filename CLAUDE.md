# Genesis — как работим (пести токени)

Този файл се зарежда сам във всяка сесия. Спазвай го буквално.

## Начало
1. Чети само `NEXT_STEPS.md`. Не чети `docs/history/`, `README.md`, цели
   модули или стари комити, освен ако стъпката изрично го иска.
2. Вземи първата точка от „Без лаптоп“. Ако всичко иска лаптопа — кажи кое
   и спри.
3. Подготовка на средата (веднъж): `pip install -q -e '.[dev,signing]'
   mypy==2.3.1 ruff==0.16.8`.

## Малки стъпки
- Една стъпка = една промяна = един комит (до ~100 реда diff). Голяма точка
  се цепи на стъпки и се записва така в `NEXT_STEPS.md`.
- Намиране: `Grep` за символа → `Read` само нужните редове (`offset`/`limit`).
  Никога цял голям файл. Без агенти/Explore за нещо, което 1–2 grep-а намират.
- Независимите извиквания — в един рунд.
- Изходът на Bash винаги ограничен: `-q`, `-x`, `| tail -20`. С `| tail` във
  верига `&&` — винаги `set -o pipefail;` отпред, иначе червен pytest минава
  (2026-10-02: комит и push с 1 паднал тест).
- Без планове, обяснения и преразказ между стъпките — само действие.

## „Перфектно“ = доказано
- Промяна в поведението → тест, който пада на стария код и минава на новия
  (провери и двете).
- Преди комит, само за пипнатото:
  `python -m ruff check <файлове>` ·
  `python -m pytest -q -x <тестови файлове> | tail -5` ·
  `python -m mypy <пипнатите модули>`.
- Преди push — пълният пакет като в CI:
  `set -o pipefail; python -m ruff check . && python -m mypy genesis_agent/
  genesis_skills.py genesis_terminal_agent.py cloud/ && python -m pytest -q -x | tail -5`.
- Нищо не се твърди без изпълнение. Неизмереното се казва като такова.

## Край на стъпка
- Комит в стила на репото: `модул: какво се промени` + до 5 реда с измереното.
- `NEXT_STEPS.md`: махни готовото (историята е в `git log`), не трупай текст.
- Отговор към оператора: до 5 реда на български — какво, с какво е проверено,
  следваща стъпка.

## Правила на проекта (не се преоткриват)
- Само терминал; без нови интерфейси и модули извън плана в `NEXT_STEPS.md`.
- Операторът е на Windows: пътища `C:\`, cp1251, PowerShell, WindowsApps
  псевдоними на `python`.
- Тестовете не стигат до мрежа и ollama (`tests/conftest.py` отказва 11434).
- Мярката за качество е `bench/projects/` (скрити тестове) — иска ключове,
  пуска се на лаптопа. Тук: само unit тестове.
- Не пипай `~/.genesis` (живи данни на оператора).
